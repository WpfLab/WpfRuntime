# WPF 重组计划文档

本文档目录用于记录当前仓库的重组进度、阶段计划和 AI 交接信息，目标是让后续对话可以直接接手推进工作。

## 文档列表

- [00-overview.md](00-overview.md)：项目目标、当前范围、已完成情况、主要缺口。
- [01-phase-plan.md](01-phase-plan.md)：分阶段执行计划、每阶段输出、风险与依赖。
- [02-next-session-handoff.md](02-next-session-handoff.md)：给下一次 AI 对话直接使用的上下文、检查清单与建议起手步骤。

## 使用方式

1. 先阅读 `00-overview.md`，了解当前仓库状态。
2. 再阅读 `01-phase-plan.md`，确认当前阶段和下一阶段任务。
3. 开始新的 AI 对话前，将 `02-next-session-handoff.md` 的内容作为输入基础。
4. 每完成一批迁移工作后，优先更新以上三个文档，再继续代码修改。

## 更新规则

- 只记录已经确认的信息，不写无法验证的结论。
- 优先记录项目引用关系、构建阻塞点、已迁移项目和未迁移项目。
- 每次推进后都要更新“当前状态”“下一步”“风险/阻塞”三个部分。
- 如发现计划顺序需要调整，应先更新阶段计划，再开始代码修改。

## 须知

1. 整个 WPF 代码仓库非常庞大，不要试图一次性迁移大量项目，建议逐个模块迁移并验证。
2. 整个 WPF 代码仓库非常庞大，不要试图将所有文件加载到你的上下文里面，你的上下文不足以进行完全加载
3. 对 origin/src 原始文件的迁移，应该采用拷贝文件的方式，而不是直接让 sln 对 origin/src 的引用。这是因为最终会将整个 origin/src 文件夹完全删除。拷贝文件的方式也方便进行对比
